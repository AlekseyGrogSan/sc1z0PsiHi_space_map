# 🛑 Правила, Задачи и Запреты для ИИ (AI Instructions & Constraints)
## Проект: «Карта пространства» (FastAPI + PostgreSQL + MinIO)

> Этот документ является обязательным набором правил для любой языковой модели (ИИ-агента), генерирующей или модифицирующей код в данном проекте.

---

## 🎯 1. Задачи ИИ (Core Objectives)

1. **Разрабатывать асинхронный бэкенд на FastAPI**: Использовать `async/await` везде, где есть I/O (база данных asyncpg, обращения к сети, очереди задач).
2. **Обеспечивать максимальную производительность медиа**: Любой медиафайл должен отдаваться посетителю в формате WebP/AVIF с минимально необходимым разрешением и кэширующими заголовками.
3. **Реализовывать ролевой доступ (RBAC)**: Четко разделять эндпоинты на публичные (быстрые, кэшируемые, анонимные) и защищенные (организатор / администратор).
4. **Оптимизировать мобильный опыт (Mobile First)**: Все структуры ответов для посетителей должны быть легковесными, не содержать избыточных полей и поддерживать прогрессивную загрузку (Blurhash + Low-res preview).
5. **Поддерживать чистую архитектуру**: Разделение на слои `api -> services -> repositories -> models/schemas`.

## ⛔ 2. Строгие Запреты (Strict Constraints & Anti-patterns)

### ❌ Запрет 1: Загрузка тяжелых файлов через FastAPI
**Категорически ЗАПРЕЩЕНО** принимать файлы панорам или 2D-чертежей через `UploadFile` напрямую в эндпоинты FastAPI (`POST /upload` с бинарным телом в памяти).
* **Почему**: Загрузка 30-мегабайтных файлов заблокирует воркеры Uvicorn и съест всю оперативную память сервиса.
* **Как делать ПРАВИЛЬНО**: Клиент запрашивает у FastAPI Presigned S3 PUT URL (`POST /upload-url`), загружает файл напрямую в MinIO, а затем шлет сигнал завершения (`POST /confirm-upload`).

### ❌ Запрет 2: Блокирующие вызовы в асинхронном коде
**Категорически ЗАПРЕЩЕНО** выполнять синхронные блокирующие операции внутри корутин `async def`:
* Синхронные вызовы стандартного `boto3` без выноса в пул потоков.
* Тяжелые математические вычисления (сшивка панорам, ресайз изображений через PIL/OpenCV).
* Синхронные обращения к БД через `psycopg2` вместо `asyncpg`.
* **Как делать ПРАВИЛЬНО**: Любая обработка медиа должна уходить в фоновые воркеры (Celery/Arq) через брокер сообщений (Redis). При необходимости разовых операций в FastAPI использовать `asyncio.to_thread` или `BackgroundTasks`.

### ❌ Запрет 3: Отдача полноразмерных оригиналов панорам без оптимизации
**Категорически ЗАПРЕЩЕНО** отдавать клиенту-посетителю ссылку на `original.jpg` панорамы (4K–8K) в основном списке или при первой загрузке.
* **Почему**: На смартфонах через мобильный 4G это приведет к зависанию интерфейса на 5–10 секунд и высокому расходу трафика.
* **Как делать ПРАВИЛЬНО**: Отдавать `preview_url` (1024×512 WebP, ~50 КБ) и шаблон кубических тайлов `cubemap_url_template`.

### ❌ Запрет 4: Рассинхронизация S3 и PostgreSQL (Orphaned Files)
**Категорически ЗАПРЕЩЕНО** удалять объекты из PostgreSQL без удаления соответствующих ключей в MinIO, или удалять файлы из MinIO, оставляя битые ссылки в БД.
* **Как делать ПРАВИЛЬНО**: Удаление медиа сущностей должно сопровождаться удалением файлов в S3 (через BackgroundTasks или транзакционный outbox), а создание сущностей должно подтверждаться только после успешной загрузки.

### ❌ Запрет 5: Хранение абсолютных URL с хостом в базе данных
**Категорически ЗАПРЕЩЕНО** сохранять в колонках БД полные URL вида `http://localhost:9000/spaces-public/image.webp`.
* **Почему**: При смене домена, переносе на продакшн-сервер или подключении CDN вся база данных станет невалидной.
* **Как делать ПРАВИЛЬНО**: В БД сохранять только **относительный S3-ключ** (`spaces/123/floors/1/plan.webp`), а полный URL генерировать на уровне Pydantic-схемы ответа или сервиса CDN.

### ❌ Запрет 6: Разрешение мутаций опубликованных данных без прав
**Категорически ЗАПРЕЩЕНО** доверять `space_id` или `floor_id` из тела запроса без проверки принадлежности ресурса текущему авторизованному пользователю (`SpaceMember`).
* Пользователь с ролью `viewer` не имеет права создавать или изменять панорамы/POI.
* Пользователь одной организации не должен иметь доступ к редактированию пространств другой организации.

## 📋 3. Стандарты написания кода для проекта

1. **SQLAlchemy 2.0**:
   - Использовать только синтаксис `Mapped[...]` и `mapped_column(...)`.
   - Использовать `select(...)` вместо устаревшего `db.query(...)`.
2. **Pydantic v2**:
   - Использовать `ConfigDict(from_attributes=True)` вместо `class Config: orm_mode = True`.
   - Использовать `@field_validator` вместо устаревшего `@validator`.
3. **Обработка ошибок**:
   - Выбрасывать типизированные `HTTPException` с понятным `detail` на английском или русском языке (например: `{"detail": "Panorama not found in this floor"}`).
4. **Работа с координатами**:
   - Все 2D координаты планов хранятся в нормализованных или пиксельных координатах чертежа с обязательным указанием масштаба `ppm` (пикселей на метр).
   - Все углы поворота панорамы хранятся в градусах: `yaw` (-180°..180°), `pitch` (-90°..90°), `heading` (0°..360° компасный азимут).
